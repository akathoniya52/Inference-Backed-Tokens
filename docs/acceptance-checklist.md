# Acceptance checklist (P9-T2)

Maps the spec's pre-mainnet checklist (`Plan.md` L596–602) and testing table (`Plan.md` L585–592) to automated tests or operator steps (H0–H13, plan §7). Mainnet (H8) starts only after every row of the pre-mainnet checklist is green.

Test ids are `file › describe › test name`. Run commands from the repo root. The api, keeper and db suites need the Mongo binary pinned by the vitest global setup, so prefix them with `MONGOMS_VERSION=7.0.14`.

`<file>` is the path relative to the package, e.g. `test/acceptance.int.test.ts`. Run it exactly like that: a path that matches nothing fails with "No test files found", whereas a `-t` filter that matches nothing silently passes.

### How the kill test works (L599)

1. The test seeds a curve model with a pool persisted in `fakeChainPools` and one 10 USDC `success` request in the period `2026-03-01T12:00Z`.
2. It spawns `node --import tsx --conditions=development src/cli/settle-once.ts --chain fake --period-start …` in `apps/keeper`, with `MONGODB_URI` set to the test database, throwaway keeper/treasury keys generated in memory, and `SETTLE_ONCE_PAUSE_AFTER_STEP=payProvider` plus `SETTLE_ONCE_PAUSE_MS=60000`. These two variables are a test-only hook in `settle-once.ts` and do nothing when unset.
3. Once the settlement reaches `paid_provider` and its `transferUsdc` is in `fakeChainTxs`, the test sends SIGKILL to the child.
4. The killed process still holds the keeper lease (TTL 90 s). The test sets `expiresAt` to the epoch, which is what a restart after the TTL would find, instead of waiting 90 s.
5. A second child runs without the hook. The test asserts that the settlement is `done`, and that `fakeChainTxs` has exactly one `transferUsdc` and one `curveBuy` for that settlement, whose signatures match the settlement doc.

The node process is spawned directly (not through `pnpm exec`/`tsx`), so SIGKILL reaches the process doing the work and not a wrapper. The test takes about 2 s.
